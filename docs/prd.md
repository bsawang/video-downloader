## 1. 项目定位

在视频平台页面上**附着**一个快速下载入口：鼠标移到视频上出现按钮，点开选清晰度，直接下载无水印文件。

核心价值是**工程底座**：新增一个平台时，只需完成一份平台适配（规则 + 字段映射）就能产出可分发产物，不需要改通用能力。

不做什么见 §3。

### M1 视频识别与数据采集 🟢
用户无感，但决定“页面上哪些视频可下载”。从页面自身的数据流中拿到视频条目（含 id、标题、作者、直链），不破解签名、不伪造请求。

### M2 清晰度解析与下载 🟢
用户点下载后，能选择不同清晰度，得到无水印文件，并看到下载进度与结果。

### M3 页面附着交互 🟢
用户能感知的部分：视频卡片/播放器上 hover 出现下载按钮，点击弹出清晰度菜单，不遮挡内容、不破坏页面布局。

### M4 平台适配 🟢
支撑“新平台快速接入”：一个平台的全部差异（站点范围、数据字段、页面锚点、下载策略）集中在一处，不改通用能力即可接入。

### M5 调研自检 🟢
支撑“快速调研产出”：对任意目标页面，能回答“采集到多少条、命中多少卡片、挂上多少按钮、多少条可下载”，用于判断适配是否完成。

### M6 构建与分发 🟢
一次构建产出可安装产物；版本号单一来源；新增平台不需要改构建脚本以外的通用代码。

### M7 平台接入（B站）🟢
在 B 站复用同一套“hover → 选清晰度 → 下载”体验，验证“新增平台 = 新增一份适配”的底座承诺。范围包括视频详情页（`/video/BV...`）与卡片页（首页 / 热门 / 排行 / 搜索结果 / 详情页右侧推荐位）。B 站以长视频为主，需支持多分P切换与超长视频落盘；1080P 及以上以单条合并档下载（画面 + 标准 AAC 音轨在浏览器内合成为一个 MP4），可合并的档位不再另列音频链接。卡片页不依赖播放页：用 `view?bvid` 取首个分P的 cid 与标题，再按同一套 playurl 取档位；多分P视频在卡片上默认只下 P1。

### M8 平台接入（小红书）🟢
在 `www.xiaohongshu.com` 复用同一套“hover → 选清晰度 → 下载”体验，验证底座在“无公开播放接口、数据全在页面状态里”的站点上也成立。范围包括发现页视频卡片与笔记详情页（`/explore/<id>`、旧路径 `/discovery/item/<id>`，含从卡片点开的弹层）。笔记详情数据直接读页面内联的 `__INITIAL_STATE__`；卡片只有笔记 id 与 `xsec_token`，档位在 hover/点击时用同一份令牌请求笔记页 HTML 现取。图文笔记不注入按钮。签名直链点选时重新解析，并把 `http://` 直链升为 `https://`（https 页面上 http 直链会被混合内容拦截）。

### M9 平台接入（YouTube）🟢
在 `www.youtube.com` 复用同一套“选清晰度 → 下载”体验。范围包括视频播放页（`/watch?v=<11位id>`）、Shorts 播放页（`/shorts/<11位id>`）与列表卡片（首页、搜索结果、播放页相关推荐、Shorts 货架）。页面内联的 `ytInitialPlayerResponse` 已只下发 SABR 流（无逐档直链），因此档位由页面内调用 `youtubei/v1/player` 现取，客户端按 `VISIONOS → IOS → ANDROID_VR` 依次兜底（`VISIONOS` 能给出 1440p/2160p 的 AV1 MP4，且直链可分段下载）。同分辨率按容器优先选流（MP4 优先于 WebM），MP4 画面 + AAC 合成一条合并档，1440p/2160p 也走 AV1 MP4 + AAC 合并；单文件已覆盖的档位不再重复列画面；仅当某档只有 WebM/VP9 或无 AAC 音轨时，才列「画面（无音轨）」并另附一条 AAC 音频。直链点选时重新取；取到的新链先探测可用性，被拒（签名失效）就换客户端，节点不可达就换节点，旧链也要探测通过才用；全部不可用时明确提示「YouTube 直链被拒绝，请刷新页面后重试」，不再产出残缺文件。卡片按钮常显：YouTube 的 hover 预览会插入一个覆盖缩略图的全局播放层（`#video-preview`），指针进入预览层后卡片不再 `:hover`，hover 揭示会把按钮藏掉。直播、播放列表、会员/年龄限制视频不在范围。

### M10 音视频合并下载 🟢
现代站点的 1080P 及以上多为分离流（画面与音轨两个文件）。用户点一个清晰度，应得到**一个可直接播放的 MP4**，不再需要自己拼：脚本内置零依赖的 fMP4（ISO BMFF）分片合并，在浏览器内把两路 MP4 无损拼成「一条视频轨 + 一条音轨」，不重新编码。合并只在两路都是分片 MP4 时进行（YouTube 的 AVC/AAC、B站 DASH 的 AVC/HEVC/AAC）；WebM/VP9+Opus、无 AAC 音轨等不兼容组合保留原有「画面/音频」分开下载，并在菜单上明示。

## 3. 非目标

- 本轮**不新增功能、不改交互**，只做结构重构，行为必须等价。（阶段 0；M7 为阶段 1 的首个平台接入，独立列示）
- 不接新平台（YouTube 范围为播放页与列表卡片，见 M9；B站范围为详情页与卡片页，见 M7；小红书范围为发现页卡片与笔记详情页，见 M8）。
- 小红书搜索页、个人主页、图文笔记不在本轮范围：前两者需登录，当前环境无法验证；图文笔记无视频可下。
- YouTube 直播、播放列表、会员/年龄限制视频不在范围：前两者需要额外授权或独立播放器结构，后者需要账号权限；视频由 InnerTube 移动端客户端（`VISIONOS` 优先）取直链，不自行破解签名。
- B 站与 YouTube 的**合并**只做「分片 MP4 无损搬箱」：不做转码/重编码，不改变编码与画质；WebM/VP9+Opus、FLAC、杜比等不兼容组合不合并，保留分离流（B站分段单文件视频 `durl.length > 1` 仍提示不支持）。
- 不做云端 ffmpeg / 下载队列服务：合并在浏览器内完成，临时数据只落本地 OPFS，不上传任何内容。
- 不实现 `GM_download`；长视频落盘走浏览器 File System Access（见 M7.2）。
- 不产出 MV3 扩展新版本；`extension/` 冻结为回归沙箱。
- 不做远程下发适配、不做独立 UI、不做常驻后台。
- 不做 Web/后端版。
- 不破解平台签名、不做指纹伪装/代理/验证码。
